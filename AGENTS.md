# AGENTS.md

Guidance for AI coding agents (Claude Code, Cursor, Codex, Copilot, Antigravity, …) working in this repository. Humans: see [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## What this project is

BetterGovPH Status is an uptime, latency and content-freshness monitor for Philippine government websites.

- **`functions/`**: one Cloudflare Worker (Hono). It does the following:
  - serves `/api/*` plus the agent-discovery files (`/llms.txt`, `/llms-full.txt`, `/robots.txt`, `/sitemap.xml`, `/status.md`)
  - runs cron-triggered checks
  - consumes the Queue
- **`src/`**: the Vite + React 19 + Tailwind v4 SPA, served as static assets by the same Worker.
- **`supabase/`**: Postgres migrations. Every object is prefixed `bgovph_`.
- **`src/data/`**: data-as-code monitor definitions, validated by JSON Schema and bundled into the Worker.

## Commands

```bash
npm install
npm run typecheck      # tsc for SPA + Worker; must pass
npm run lint           # eslint, zero warnings allowed
npm run test:unit      # vitest (functions/__tests__, src/**/__tests__)
npm run validate:data  # JSON Schema validation of src/data
npm run build          # production build
npm run functions:dev  # Worker on http://127.0.0.1:5525
npm run dev            # SPA on http://localhost:5125 (proxies to Worker)
```

Before you say a change is done, run `npm run typecheck && npm run lint && npm run test:unit`. If you touched `src/data`, also run `npm run validate:data`.

## Rules

### Monitor data

- A `slug` must be unique across all files and match `^[a-z0-9-]+$`.
- **Never rename an existing slug.** Historical rows in `bgovph_checks`, `bgovph_daily_stats` and `bgovph_incidents` are keyed by slug.
- A monitor's `category` must already exist in `src/data/categories.json`.
- To refresh imported monitors, change `scripts/import-bettergov-websites.ts` and re-run the importer. Don't edit the generated JSON.

### Database

- Migrations live only in `supabase/migrations/`, use timestamped filenames, and prefix every object `bgovph_`. `functions/__tests__/migrations-prefix.test.ts` enforces this.
- Prefer one RPC per batch. Workers have a 50-subrequest limit (see `docs/architecture.md`).

### API and agent surface

- **Public GET endpoints are open-CORS (`*`). Mutating endpoints are not.** `POST /api/trigger` requires local dev or `Authorization: Bearer $TRIGGER_SECRET`. Don't weaken this.
- **When you add or change a public route, also update:**
  - `functions/agent/openapi.ts` (a test fails if a GET route is missing from the spec)
  - `functions/agent/llms.ts`
  - the `run_worker_first` list in `wrangler.jsonc` and the dev proxy in `vite.config.ts`, if the route is outside `/api/*`
- Discovery files (`llms*.txt`, `robots.txt`, `sitemap.xml`, `openapi.json`) must be built only from bundled data, with no Supabase calls, so they keep working during database outages.
- Build absolute URLs with `getSiteUrl(c)` (from `SITE_URL`, falling back to the request origin). Never hard-code a domain.
- `robots.txt` policy: AI agents that fetch pages to answer a user are allowed; AI-training crawlers are blocked. Keep to this unless the maintainers decide otherwise.

### Code style

- TypeScript strict mode, with no unused locals or params. Format with Prettier (`npm run format`).
- Commits follow Conventional Commits (`feat:`, `fix:`, `docs:` …), enforced by commitlint and Husky.
- Match the existing BetterGov.ph design-system components in `src/components/ui`. Don't add a new UI library.

### Security

- Never commit `.dev.vars`, `.env`, or Supabase service-role keys.
- Probes must keep their honest `USER_AGENT` and their 16 KB body-read limit. Don't add scraping or full-page storage.
